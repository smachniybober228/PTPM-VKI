## 3. Техническое задание: Функция `validate_password`

В модуле `src/password_validator.py` требуется реализовать функцию:

```python
def validate_password(password: str) -> bool:
    """
    Выполняет валидацию строки пароля на соответствие политикам безопасности.
    
    :param password: Проверяемый пароль
    :return: True, если пароль удовлетворяет всем условиям, иначе False
    :raises TypeError: Если входной параметр не является строкой
    :raises ValueError: Если входная строка содержит символы пробела
    """
```

### 3.1. Этап 1: Проверка входных данных и генерация исключений
Данные проверки должны срабатывать до начала анализа структуры пароля:

1. **Контроль типа аргумента (`TypeError`):**
   * Если аргумент `password` не принадлежит типу `str` (`None`, `int`, `float`, `list`, `dict` и т.д.), функция обязана немедленно выбросить исключение:
     ```python
     raise TypeError("Пароль должен быть строкой")
     ```
2. **Контроль пробельных символов (`ValueError`):**
   * Пароль не должен содержать пробелов (символ `' '`, ASCII-код 32) ни в начале, ни в середине, ни в конце строки.
   * При наличии хотя бы одного пробела функция обязана немедленно выбросить исключение:
     ```python
     raise ValueError("Пароль не должен содержать пробелы")
     ```

### 3.2. Этап 2: Проверка критериев валидности пароля
Если исключения не были возбуждены, строка анализируется на соответствие пяти критериям безопасности. Функция возвращает `True`, если выполнены **все** условия, и `False`, если нарушено хотя бы одно из них:

1. **Длина строки:** от 8 до 20 символов включительно ($8 \le \text{len}(password) \le 20$).
2. **Заглавные буквы:** содержит как минимум одну заглавную букву (поддерживаются как латиница `A-Z`, так и кириллица `А-Я`, проверка методом `.isupper()`).
3. **Строчные буквы:** содержит как минимум одну строчную букву (латиница `a-z`, кириллица `а-я`, проверка методом `.islower()`).
4. **Цифры:** содержит как минимум одну десятичную цифру (`0-9`, проверка методом `.isdigit()`).
5. **Специальные символы:** содержит как минимум один символ из строго определённого алфавита:
   $$\Sigma_{\text{spec}} = \{ \texttt{!}, \texttt{@}, \texttt{\#}, \texttt{\$}, \texttt{\%}, \texttt{\^}, \texttt{\&}, \texttt{*} \}$$
   *(Символы `_`, `-`, `?`, `.`, `,` в этот список не входят и специальными символами по условию ТЗ не признаются).*

## 4. Требования к тестовому набору (`unittest`)

В модуле `tests/test_password_validator.py` создайте тестовый класс `TestPasswordValidator`, унаследованный от `unittest.TestCase`.

### 4.1. Архитектурные требования к тестам
* Тесты должны быть изолированными и атомарными (один тестовый метод проверяет одну изолированную гипотезу).
* Имена методов должны начинаться с префикса `test_` и однозначно описывать сценарий (например, `test_missing_digit`, `test_boundary_length_8`).

### 4.2. Обязательный состав тестовых методов:
1. **Позитивное тестирование:**
   * Проверка корректного пароля на латинице (`self.assertTrue(...)`).
   * Проверка корректного пароля на кириллице (`self.assertTrue(...)`).
2. **Анализ граничных значений длины (BVA):**
   * Длина 7 символов (на 1 меньше границы) $\to$ `self.assertFalse(...)`.
   * Длина 8 символов (нижняя граница) $\to$ `self.assertTrue(...)`.
   * Длина 20 символов (верхняя граница) $\to$ `self.assertTrue(...)`.
   * Длина 21 символ (на 1 больше границы) $\to$ `self.assertFalse(...)`.
3. **Классы эквивалентности (неполный состав символов):**
   * Пароль без заглавных букв $\to$ `self.assertFalse(...)`.
   * Пароль без строчных букв $\to$ `self.assertFalse(...)`.
   * Пароль без цифр $\to$ `self.assertFalse(...)`.
   * Пароль без специальных символов $\to$ `self.assertFalse(...)`.
   * Пароль со спецсимволом, не входящим в перечень (например, `_` или `?`) $\to$ `self.assertFalse(...)`.
4. **Тестирование исключительных ситуаций:**
   * Проверка выброса `ValueError` при наличии пробелов (внутри, в начале, в конце) через контекстный менеджер `with self.assertRaises(ValueError):`.
   * Проверка выброса `TypeError` при передаче некорректных типов данных (`None`, `int`, `list`) через `with self.assertRaises(TypeError):`.

## 5. Инструкция по работе в Git Bash

Все команды выполняются в консоли **Git Bash** из корневого каталога репозитория.

### Шаг 1. Актуализация ветки main и создание рабочей ветки
```bash
git checkout main
git checkout -b cut_knowelage
```

### Шаг 2. Разработка
* Реализуйте функцию в `src/password_validator.py`.
* Реализуйте тесты в `tests/test_password_validator.py`.

### Шаг 3. Запуск и отладка тестов
Запустите обнаружение и выполнение модульных тестов:
```bash
python -m unittest discover -s tests -v
```
Все тесты должны завершаться с вердиктом `OK`.

### Шаг 4. Контроль покрытия кода тестами (Coverage)
Запустите профайлер покрытия строк рабочего модуля `src`:
```bash
python -m coverage run --source=src -m unittest discover -s tests -v
python -m coverage report -m
```
> **Требование:** покрытие строк файла `src/password_validator.py` должно составлять **100%**.

### Шаг 5. Фиксация изменений в репозитории
Убедитесь, что в коммит не попадут посторонние файлы:
```bash
git status
```
Проиндексируйте и закоммитьте только рабочие файлы:
```bash
git add src/password_validator.py tests/test_password_validator.py
git commit -m "feat: implement password validator and unit tests"
```
> **Важно:** Запрещено добавлять кэш (`__pycache__`), виртуальное окружение (`venv/`), отчеты (`.coverage`, `htmlcov/`) и файлы IDE (`.idea/`, `.vscode/`).

### Шаг 6. Отправка ветки в удалённый форк
```bash
git push -u origin cut_knowelage
```
